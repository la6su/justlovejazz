Glassmorphism on WebGPU

Real glass — not the CSS backdrop-filter approximation. Transmission, clearcoat, iridescence, and a CubeCamera reflection that updates per frame. Here's how we made it work across WebGPU and WebGL2 with bit-identical output.

The material

We used a single MeshPhysicalMaterial with these properties: 

transmission: 0      // solid glass, not see-through
iridescence: 1.0      // thin-film interference (soap bubble)
clearcoat: 1.0        // glossy top layer
roughness: 0.05       // polished
metalness: 0.0        // dielectric
envMapIntensity: 2.0  // boost reflections

The transmission: 0 is deliberate — we wanted reflections and iridescence, not refraction. A CubeCamera renders the content scene into a 256×256 cubemap every frame, used as material.envMap.

The cube camera problem

A CubeCamera renders 6 views (one per face). At 256×256, that's 6 draw calls per frame just for reflections. On mid-range hardware, this was 4ms — a quarter of our frame budget.

The fix: render the CubeCamera only when the glass object is visible. Our on-demand rendering pipeline already gated renderer.update() behind a _needsRender flag. We added a check: if the glass mesh is not in the camera frustum, skip the CubeCamera update entirely. Idle frames drop to 0 draw calls.

"The cube hidden during CubeCamera render to avoid self-reflection" — this comment in the codebase is the single most important detail. Without it, you get a black cube reflecting itself into infinity.

Iridescence parity

The thin-film interference approximation in MeshPhysicalMaterial uses a different code path on WebGPU (TSL) vs WebGL2 (GLSL). The visual difference is sub-perceptual, but we wanted bit-identical output for our parity guarantee.

The solution: a portable integer hash for the iridescence noise, identical in both shaders. We could not use sin()-based hashing — precision differs between GLSL and WGSL. The integer hash fract((p3.x+p3.y)*p3.z) with p3 = fract(vec3(p.xyx)*0.1031) is bit-identical across both.

Edges with rainbow vertex colors

The glass cube has EdgesGeometry — 12 edges (not 24 from separate planes). Each vertex gets an animated rainbow HSL color. This is the detail that makes the cube feel alive — the edges shimmer independently of the glass body.

Vertex colors are set directly on the geometry's color attribute, updated each frame. No uniform overhead, no draw call increase. The edges render in the same pass as the glass body.

Result

A glass cube that reflects its surroundings, shimmers with iridescence, and has rainbow edges. It runs at 60fps on WebGPU, 60fps on WebGL2 (same material, different backend), and 0fps when idle (on-demand rendering). The visual identity is the centerpiece of the portfolio — every visitor sees it within 2 seconds of entering.
