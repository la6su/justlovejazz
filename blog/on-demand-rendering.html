On-Demand Rendering — Zero Idle Draw Calls

The 3D portfolio looks alive, but when you're not interacting, the GPU sleeps. Here's the architecture that makes it possible — and the one exception that keeps the scene from feeling dead.

The problem with rAF

The default Three.js pattern is requestAnimationFrame(loop) — render every frame, 60 times a second, forever. For a 3D portfolio where the user spends 80% of their time reading text, this means 4,800 draw calls per minute of idle. On a laptop, the fan spins up. On mobile, the battery drains.

We wanted the opposite: zero draw calls when idle. The scene should render only when something changes — a section transition, a carousel spin, a cursor movement that affects the 3D layer.

The _needsRender flag

The core idea is a single boolean: _needsRender. The render loop checks it each frame: 

setAnimationLoop(() => {
  if (_needsRender) {
    renderer.update()
    _needsRender = false
  }
})

When the flag is false, renderer.update() is never called. The GPU sleeps. The animation loop still runs (cheap — just a boolean check), but no render work happens.

The flag is set to true by events that change the scene:

  • JoystickNav section change — cube rotates to new face
  • BakuCarousel morph/scroll — carousel ring animates
  • Splash/intro animation — opening sequence
  • Camera shake — burst effects
  • ParticleBurst — active bursts

Ambient breathing — the one exception

A fully frozen scene feels dead. We added a single exception: every 2.5 seconds, one render frame fires to advance the worldDNA time uniform. This gives a subtle "breathing" — particles drift, the background gradient shifts, the glass cube's iridescence animates. Then the GPU sleeps again.

The breathing respects prefers-reduced-motion — if the user has requested reduced motion, the scene is truly frozen between interactions.

"On-demand rendering: don't set _needsRender=true permanently. Event-driven only. Ambient breathing (1-frame refresh every ~2.5s in idle) is the ONLY exception."

— JUSTLOVEJAZZ engineering principle

What we measured

State Draw calls/frame GPU time
Idle (no breathing) 0 0ms
Idle (breathing frame) ~12 3ms
Section transition ~15 5ms
BakuCarousel scrolling ~18 8ms

Over a 60-second idle period: 24 breathing frames × 3ms = 72ms total GPU time. Compare to rAF: 3600 frames × 5ms = 18,000ms. That's a 250× reduction.

The catch

On-demand rendering makes the codebase harder to reason about. Every animation must explicitly set _needsRender = true — forget it, and the animation plays in your head but not on screen. We added a lint rule and a DevPanel toggle to force-render during debugging.

The CubeCamera reflection (for the glass cube) also needs the flag — if the cube is visible but _needsRender is false, the reflection is stale. We accept this: the reflection updates on the next interaction, which is usually within a second.
